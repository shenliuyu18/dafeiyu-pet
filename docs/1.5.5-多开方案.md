# 大肥鱼桌宠 · 1.5.5 多开方案

> 基线版本：v1.5.4（commit `e1baa9e`）
> 状态：**已实现**（2026-11-26），实施细节见文末「实施记录」。
> 平台范围：仅 Windows（跨平台方案另见 `docs/1.6.0-跨平台方案.md`，已暂缓）。

* * *

## 一、决策记录（2026-11-26）

| 决策 | 结论 |
| --- | --- |
| 数量上限 | **不设硬上限**，超过 4 只时弹确认并显示资源消耗；技术上限 16 槽（防误触失控） |
| 状态划分 | **设置共享、形象独立**：语言/尺寸/字体/音效/Key/账本设置全局共用；形象、位置、心情、番茄钟各自独立 |
| 托盘 | **单一托盘**，由主实例（最小存活槽位）持有；主实例退出后自动接管 |
| 副实例行为 | **全部漫游、各自发声**；提供"仅主实例发声"开关（默认关） |

## 二、现状约束（已核实）

| 机制 | 现状 | 多开下的冲突 |
| --- | --- | --- |

## 三、路线选择

| 路线 | 做法 | 结论 |
| --- | --- | --- |
| **A. 多进程** | 每只宠物一个进程，槽位锁 + 共享状态 + 本地 IPC | **采用**：崩溃隔离、复用现有代码、约 2 周交付 |
| B. 单进程多窗口 | 手动创建多个 WebView | 不做：Wails v2 不支持多窗口 |
| C. 单窗口多宠物 | 一个全屏窗口画多只，Region 取并集 | 暂不：渲染层大改，留给 1.6+ |

## 四、进程模型

### 4.1 槽位与单实例锁

- 槽 1 沿用原互斥名 `Global\dafeiyu-desktop-pet-wails`
- 槽 2–16：`Global\dafeiyu-desktop-pet-wails-slotN`
- Lite 继续加 `-lite` 后缀，完整版与 Lite 可各开一组，互不干扰
- 启动顺序：从槽 1 起依次尝试 `CreateMutex`；全部占用则激活主实例并提示
- 进程退出或崩溃时系统自动释放互斥，不会留下死槽
- **再次双击 exe = 再养一只**，无需新入口

### 4.2 存活探测

- 用 `OpenMutexW(SYNCHRONIZE)` 探测某个槽是否存活，不抢占
- 主实例 = 存活槽位中编号最小者
- 每 2 秒探测一次，用于托盘接管与会话统计

### 4.3 进程间通信

- 每实例监听 `127.0.0.1` 随机端口
- 端口与随机 token 写入 `instances\<slot>.json`，文件权限 0600
- 只接受带 token 的请求，只绑定回环地址，不暴露局域网
- 命令集最小化：`ping / show / hide / quit / refresh`；副实例的托盘气泡通过 `notify` 转交主实例
- 调试桥改为 `9336 + slot - 1`（仅 `--dev-debug` 开启）

## 五、状态文件

### 5.1 布局

```
%APPDATA%\dafeiyu-desktop-pet\
  dafeiyu-state.json          共享设置（沿用原文件名）
  ledger-cache.json           主实例拉取的账本缓存
  restore.json                上次会话的槽位集合
  instances\1\state.json      槽 1 运行时状态
  instances\1\endpoint.json   端口 + token（0600）
  instances\2\...
  characters\...              现有形象包目录（共享）
  fonts\...                   现有字体目录（共享）
```

### 5.2 字段划分

| 共享（根 `dafeiyu-state.json`） | 独立（`instances\<slot>\state.json`） |
| --- | --- |
| `lang` `scale` `fontFamily` `fontSize` `fontWeight` | `character` `pos` `dock` |
| `sfx` `autoActionSec` `powerSave` `fullscreenHide` | `satiety` `mood` `awake` |
| `ledger` `ledgerSource` `deepseekKey` `apiKeys` | `pomo` 运行状态、剩余时间 |
| `autoUpdate` `lastUpdateCheck` `lastResumeRestart` | — |
| `customQuips` `useCustomQuips` `pinnedActions` | — |
| `pomoHistory`（统计合并读）、`lang` 等 UI 偏好 | — |

### 5.3 并发写

- 共享文件：命名互斥 `Global\...-state-lock` + 读-改-写合并；任何实例改设置都走这条路径
- 实例文件：只有本实例写，无竞争
- 统计页读取所有槽位文件后汇总，不引入共享写

### 5.4 迁移

1. 首次 1.5.5 启动：备份 `dafeiyu-state.json` 为 `.bak-<时间戳>`
2. 运行时字段复制到 `instances\1\state.json`
3. 从共享文件删除运行时字段
4. 幂等：已存在 `instances\1\` 则跳过
5. 回滚到 1.5.4 时共享文件仍可读（缺字段用默认值），不保证多开信息保留

## 六、协调机制

### 6.1 托盘选举

- 只有主实例创建托盘图标
- 副实例启动时若无托盘，不创建
- 每 2 秒检查：若自己已成为最小存活槽且无托盘 → 创建；若自己不是主实例且持有托盘 → 销毁
- 主实例退出后，下一槽位在 2 秒内接管，托盘不消失
- 托盘菜单：宠物列表（角色名 + 显示/隐藏勾选）、「再养一只」、「全部显示/隐藏」、「全部退出」、设置

### 6.2 账本

- 只有主实例执行周期性网络拉取（5 个平台），结果写 `ledger-cache.json`
- 副实例周期"刷新"改为读缓存，不发网络请求
- 用户手动「重新检测」允许任意实例直连一次
- Key 保存后由发起实例通知主实例立即刷新

### 6.3 形象包与字体

- 跨进程命名互斥：`Global\...-pack-<id>`、`Global\...-fonts`
- 撞锁时提示"另一只正在安装，请稍后再试"
- 安装完成后广播 `reload-characters`，各实例重新扫描目录

### 6.4 更新

- 只有主实例检查更新与下载（共享 `lastUpdateCheck` 去重）
- 安装前广播 `quit`，等待全部退出（最长 5 秒，超时强制结束）
- 安装器结束后以 `--restore-session` 拉起，恢复上次的槽位集合

### 6.5 自启动与会话恢复

- 计划任务改为 `<exe> --restore-session`
- 该模式读取 `restore.json`，为每个槽位启动一个 `--slot=N` 子进程，然后退出
- 无 `restore.json` 时按单实例启动
- 槽位集合变化时（新增/关闭）由主实例原子写 `restore.json`

### 6.6 全屏、省电、音效

- 全屏避让：每实例独立判定，行为一致
- 省电模式：每实例独立生效
- 音效与通知：默认全部发声（用户选择）；设置里提供「仅主实例发声」开关
- 通知气泡：副实例通过 IPC 请主实例弹出，标题带角色名，避免被丢弃

## 十三、实施记录（2026-11-26）

落地文件：

| 文件 | 内容 |
| --- | --- |
| `wails/instance.go` | 槽位互斥、存活探测、端点文件与 IPC、会话恢复、实例巡检与托盘选举 |
| `wails/state_split.go` | 共享/运行时字段拆分、三方合并写、迁移、多实例专注统计 |
| `wails/ledger_cache.go` | 主实例写账本缓存，副实例读缓存 |
| `wails/instance_test.go` | 槽位命名、字段拆分、路径、restore 读写、合并写、迁移、共享重载 |

与设计的两处偏差：

1. **`restore.json` 改为「启动登记 / 主动退出移除」**。原设计由主实例按存活槽位重写，主实例被强杀时会把列表缩小，导致下次开机少恢复一只。实测确认：强杀主实例后列表仍为 `[1,2]`，主动退出后才变为 `[1]`。
2. **槽位上限仍是 16**（按你的决定保留），超过 4 只弹系统确认框，不做实时资源采样。

真机验证（隔离实例 `--isolated --dev-debug`，Windows 11 / 150% DPI）：

- 两只同屏：槽 2 斜向错开 64×48 px，槽 1 `leader=true trayReady=true`，槽 2 `leader=false trayReady=false`
- 状态拆分：根 `dafeiyu-state.json` 只剩共享字段（含 `onlyPrimarySound`），`instances/1|2/dafeiyu-state.json` 各自持有 `character/pos/satiety/mood/awake/pomoHistory`；迁移前自动生成 `.bak-<时间戳>`
- 强杀主实例：槽 2 在 2 秒内接管托盘（`leader=true trayReady=true`），`restore.json` 不被缩小
- `quitAll()`：两只进程全部退出，端点文件清理，`instances/` 只剩状态目录
- `--restore-session`：按 `restore.json` 拉起两只，`ping` 分别返回 `slot=1 primary=true` 与 `slot=2 primary=false`
- 界面：右键菜单在单只时显示「退出」，多只时显示「关闭这只 / 全部退出」；设置 → 多开 页正常显示只数与本机角色
- 共享设置实时同步：在宠物 A 上改语言/尺寸/字体/音效/仅主发声后，宠物 B 的界面与行为立即跟随（实测 B 的语言切到 en、音效 off、缩放到 1.2）；安装形象包后另一只的商店列表立即从「下载」变为「卸载」，无需重启
- 同步覆盖面：设置保存、API Key、自定义互动文字（WordsSave）、形象包安装/卸载都会广播；卸载别人正在用的形象包时，本实例自动回落到内置形象，不会停在空动作表
- 位置/缩放只在值真的变化时重放，避免某只改声音时另一只被拉回右下角


验证命令与门槛：`go test ./...`、`npm run test:frontend`、`npm run typecheck`、`node tools/renderer-smoke.js` 全部通过。

### 追加修复（同日）

- **8 只时无法退出**：复现时日志出现多次 `lock: timeout ...-state-lock`。根因是退出与定时保存要写共享状态，而旧的命名互斥用无限等待；一旦互斥所有权因为 Go 协程跨线程调度而丢失，后来者永远等不到。现在：加锁期间 `LockOSThread` 钉住线程、最多等 3 秒、`Quit` 增加 5 秒强制退出兜底；端点文件改到 `beforeClose`（真正开始关闭）才注销，卡住时仍可从托盘重试。实测 8 只 `quitAll` 1.1 秒全部退出，无锁超时、无强制结束。
- **确认框位置**：超过 4 只时的确认改由发起方弹出（子进程弹框会让人以为点击无效）。
- **托盘响应性**：`QuitAll` 改为后台执行，不再占用托盘窗口线程。

- **新多开时整屏闪一下**：逐帧分析用户录屏（30fps）看到整屏纯黑帧，只剩宠物本身。仅把 Region 收到 1×1 仍会闪：Wails 的透明窗口是分层窗口，DWM 合成时不看 Region。最终改为「定位后先不显示」，等前端上报首帧位置、再等一帧（约 60ms）才 `ShowWindow`；2.5 秒兜底强制显示。日志实测 `show deferred_ms≈356`，5 只连续添加无黑屏。
- **数量提醒开关**：设置 → 多开新增「超过 4 只时先确认 / 不再提示」，共享设置 `multiWarnOff`，关闭后连续加到 5 只不再弹窗（实测 5 进程、无对话框）。
