## 一、为什么当时没直接编三端（现状体检）

1.5.4 的后端在编译层面绑定 Windows，实测：

```
GOOS=darwin  go build ./...  → imports golang.org/x/sys/windows: build constraints exclude all Go files
GOOS=linux   go build ./...  → 同上（windows/registry 同样失败）
```

| 层 | 文件 | 行数 | 内容 |
| --- | --- | --- | --- |
| 窗口 | `wails/win32.go` | 793 | 透明/置顶/Region/点击穿透/光标轮询/拖动 |
| 全屏 | `wails/fullscreen_windows.go` | 691 | QUNS + 窗口类名 + DWM cloak + 自愈 |
| 托盘 | `wails/tray_windows.go` | 408 | Shell_NotifyIcon 自绘 |
| 系统 | `wails/autostart.go`、`power.go`、`fonts.go` | — | 计划任务、WM_POWERBROADCAST、字体枚举 |
| 更新 | `wails/update.go` | 594 | 下载 exe → 退出 → 替换 |
| 单实例/加密 | `wails/main.go`、`state.go` | — | CreateMutex、DPAPI |
| 打包 | `.github/workflows/release.yml`、`tools/wails-build.js` | — | 仅 windows-latest + NSIS |

注意：`win32.go`、`autostart.go`、`power.go` **没有 `_windows` 后缀**，Windows 依赖是硬编译进去的，这是跨编译失败的直接原因。

可复用面（比想象中大）：

- `renderer/` 606 KB，纯 HTML/CSS/JS，不依赖平台；
- `wails/frontend/dist/assets.zip` 38,160,690 B（约 37 MB），纯资源；
- 形象包 1.0.1 标准与 `pack_migrate.go` 的迁移逻辑；
- 后端约一半纯 Go：state / ledger / i18n / characters / pomo / words / assets / pack_migrate（约 5000 行）；
- `wails/fullscreen_logic.go` 的滞回状态机与平台无关，三端可直接共用，只替换"探测函数"。

结论：移植成本集中在**窗口层与系统集成层**，业务逻辑和渲染层几乎可以整体复用。

## 三、目标架构

```
internal/core（纯 Go，无平台依赖）
  state / ledger / i18n / characters / pomo / words / assets / pack_migrate
        ↑ 接口
internal/platform.Provider ── windows / darwin / linux / androidstub
        ↑ 宿主
  ① Wails v2 宿主（Win / macOS / Linux，cgo）
  ② Android WebView 悬浮窗宿主（Kotlin）
        ↑
  同一份 renderer  ← 资产：desktop = assets.zip；android = WebP 序列 profile
```

设计原则：

- **接口化，不堆条件编译**：`Window`（移动/置顶/穿透/焦点）、`Screen`（工作区/DPI/光标）、`Fullscreen`、`Tray`、`Notifier`、`SecretStore`（DPAPI → Keychain → libsecret → EncryptedSharedPreferences）、`Autostart`、`Power`、`Updater`、`AppPicker`、`SingleInstance`、`Fonts`。
- **渲染层一份**：`wails/frontend/api.js` 是唯一平台接触面，抽象一层 bridge adapter；Android 用 `@JavascriptInterface` 提供同名方法，业务 JS 零改动。
- **不换技术栈**：macOS/Linux 继续 Wails + 系统 WebView（WKWebView / WebKitGTK），不回到 Electron/Tauri；Android 不移植 Go，用 Kotlin 宿主。

目录改造（M0）：

```
wails/
  internal/core/        纯 Go 业务
  internal/platform/    接口 + windows / darwin / linux 实现
  main.go               只做装配
renderer/               一份，新增 bridge 适配层
android/                独立 Gradle 工程（Kotlin + 复用 renderer 资源）
tools/                  build-android-assets.py / package-macos.js / package-linux.js
```

## 五、macOS 方案

| 能力 | 实现方式 |
| --- | --- |
| 透明/无边框/置顶 | Wails 原生透明 + frameless；NSWindow level 提到 floating；`collectionBehavior = canJoinAllSpaces` |
| 点击穿透 | 窗口缩到宠物包围盒；约 60 ms 轮询 `NSEvent.mouseLocation`（不求辅助功能权限），命中测试复用渲染层上报的 boxes，命中区外 `setIgnoresMouseEvents:YES` |
| 全屏避让 | `CGWindowListCopyWindowInfo` 只看 bounds / layer / PID（不读窗口标题 → 不触发屏幕录制权限）；前台窗口铺满屏幕即判定，沿用现有滞回参数 |
| 托盘 | cgo NSStatusItem + NSMenu，UI 调用统一走主线程 `dispatch_async` |
| 开机自启 | `~/Library/LaunchAgents/*.plist` |
| 通知 | UNUserNotificationCenter；失败降级为不弹 |
| 凭据 | Keychain（kSecClassGenericPassword） |
| 单实例 | `flock` 文件锁 + 已运行则激活窗口 |
| 更新 | 检查 Release → 下载 dmg → 校验 SHA256 → `open`，不做静默替换 |
| 打包 | CI macOS runner 出 universal .app（arm64 + x86_64）；`codesign --deep -s -` 临时签名；`hdiutil` 出 dmg |

限制（必须写进文档与下载页）：

- 未签名/未公证：首次启动被 Gatekeeper 拦，需右键 → 打开；系统升级或移动 .app 后可能在"隐私与安全性"重新放行。
- 无自动静默更新，只有"下载并打开 dmg"。

## 六、Linux 方案（X11）

| 能力 | 实现方式 |
| --- | --- |
| 透明 + 穿透 | GTK3 RGBA visual + `gtk_widget_input_shape_combine_region`（cairo region 来自 boxes） |
| 置顶 | `gtk_window_set_keep_above` |
| 全屏避让 | Xlib EWMH：`_NET_ACTIVE_WINDOW` + `_NET_WM_STATE_FULLSCREEN`，复用滞回状态机 |
| 托盘 | StatusNotifierItem（DBus，godbus 已在依赖）；GNOME 需 AppIndicator 扩展，缺扩展时右键菜单兜底 |
| 自启 | `~/.config/autostart/*.desktop` |
| 通知 | `org.freedesktop.Notifications` DBus |
| 凭据 | libsecret；不可用时降级为 0600 本地文件并提示 |
| 更新 | AppImage 自替换（校验哈希）；deb 引导到 Release 页面 |
| 打包 | ubuntu-22.04 runner 构建（glibc 2.35，覆盖 Debian 12 / Ubuntu 22.04+）；AppImage + deb（nfpm） |

Wayland：启动检测 `XDG_SESSION_TYPE=wayland`，一次性提示"无法定位窗口、穿透不可靠"，提供"仍要运行 / 退出"。

## 七、Android 方案（系统级悬浮宠物）

**体验定位**：悬浮陪伴 + 番茄钟 + 提醒，不是"手机上养鱼的独立 App"。

- 宠物浮在任意应用之上，可拖动，靠近屏幕边缘自动吸附；
- 单击互动、双击出动作、长按弹菜单；
- 气泡显示台词 / 番茄钟倒计时，半透明自动淡出；
- 通知栏常驻控制条（显示/隐藏、番茄钟、退出）；
- 设置页为普通 Activity，复用同一份 renderer 的设置界面；
- 熄屏/锁屏自动暂停；低电量降帧；前台服务保活；
- 不做：桌面启动器替代、锁屏养宠物、多宠物同屏。

**技术**：

- Kotlin + `WindowManager` `TYPE_APPLICATION_OVERLAY`，窗口尺寸 = 宠物包围盒；WebView 通过 `WebViewAssetLoader` 加载 APK 内资源；`@JavascriptInterface` 实现与 Wails 同名的方法与事件。
- 拖动在 Kotlin 侧完成（updateViewLayout），点击事件透传 WebView。
- 前台服务：API 34 使用 `specialUse` 类型；`POST_NOTIFICATIONS`、`SYSTEM_ALERT_WINDOW`、`RECEIVE_BOOT_COMPLETED`。
- 权限引导页：悬浮窗 → 通知 → 忽略电池优化（可选），未授权时逐步引导。

**素材（关键风险）**：Android WebView 的 `<video>` 经常丢 VP9 alpha。主方案为新增 android 资产 profile：现有动画转成带 alpha 的动画 WebP，用 WebCodecs `ImageDecoder` 逐帧画到 canvas（`renderer/features/sprite.js` 已有图集播放基础）。APK 只内置大肥鱼（约 15–20 MB），其余 8 个形象沿用商店按需下载（新增 `-android.zip` 变体，不改 1.0.1 包格式）。第一周先做真机 spike；若 WebView 直接支持透明视频则省掉转码，最差退 PNG 序列。

**分发**：签名 APK + 官网/酷安；Google Play 暂缓（"显示在其他应用上层"审核风险高）。

## 八、无 Mac 条件下的验收方案

| 手段 | 覆盖 | 成本 |
| --- | --- | --- |
| GitHub Actions macOS runner | 构建 universal 包、启动应用、`screencapture`、调试桥 `/state` `/boxes` 自动断言 | 公共仓库免费 |
| 本机 QEMU 虚拟机（x86_64） | 日常开发闭环：编译、改 UI、窗口行为自查 | 0（占 8 GB 内存 + 80 GB 磁盘） |
| 云端 Apple Silicon Mac（按小时） | 发版前 24 项人工清单、Retina、Metal 合成、Gatekeeper | 约 $0.1–1/小时，做 1–2 天 |

本机条件（2026-11-26 实测）：Intel Core 7 245HX（14 核）、`HypervisorPresent=True`（可用 WHPX）、内存 16 GB、C 盘剩余 186 GB。

虚拟机三个限制必须记住：

1. 只能跑 x86_64 版 macOS，**arm64（M 系列）切片测不到**；
2. 无 GPU 加速/Retina，性能与流畅度不能作为发布依据；
3. 非 Apple 硬件虚拟化 macOS 违反 Apple 许可，系统更新易碎。

**W0 预研（2–3 天）**：先在本机把 QEMU + OpenCore 跑起来，并验证 Actions GUI 冒烟脚本，再决定全速开工。

## 十、验收门槛

- **Windows**：全部 Go 单测 + 前端冒烟 + 真机点测；待机 CPU ≤ 9.6%、漫游 ≤ 23.4% 单核（抽象层不得引入退化）。
- **macOS**：24 项功能清单（首帧、穿透、拖动、置顶、全屏避让、托盘、通知、自启、Keychain、账本、形象商店、字体、番茄钟、诊断包、单实例、多屏 Retina、更新检查、退出清理…）；性能目标 ≤ Windows 的 1.5 倍（不作为硬门槛）。
- **Linux**：Ubuntu 24.04 与 Debian 12 的 X11 各跑一遍；Wayland 提示正确。
- **Android**：Android 12 / 14 / 15 真机；熄屏、锁屏、切换应用、低电量、旋转、权限拒绝六种场景。
- 三端共用 9336 调试桥导出状态做对照。

## 十二、重启条件（什么时候值得做）

满足任意两条再启动：

1. 有真实的 macOS / Linux 用户需求（issue、下载请求、社区投票）；
2. 能获得 Apple 开发者账号（消除 Gatekeeper 与静默更新障碍）；
3. 有一台可长期使用的 Mac（真机或稳定云端预算）；
4. Windows 端进入稳定期，连续两个版本无 P0 故障。

若只有 1、3 而无 2，可做"macOS 未签名版"；若 1 不成立，不做。
