# 桌宠形象包制作标准 v1

本应用支持用户自制形象包：把动作视频、封面和一份 `manifest.json` 打成 `.zip`，在
**设置 → 桌宠形象 → 从本地文件导入（.zip）** 里导入即可使用。导入时会按本文件校验，
不合格的包会给出具体错误，不会写入本机。

形象包是自包含的：台词、喂食/饥饿/睡觉回应、梗图、动作名的英/日翻译都可以写进包里。
应用本体不内置任何下载形象的文字，没装包时应用里只有商店信息（缩略图、名称、许可），
也不会出现该形象的台词或梗图。

配套工具：

```bash
python tools/character-pack/validate.py 我的形象/     # 校验文件夹或 zip
python tools/character-pack/make_pack.py 我的形象/    # 打包成 我的形象.zip
```

示例清单见 `tools/character-pack/manifest.example.json`。

---

## 1. 目录结构

```
my-neko/
├─ manifest.json          必需，清单
├─ cover.webp             必需，商店封面
├─ animations/            目录名随意，只要和清单里的 file 对得上
│  ├─ idle.webm
│  ├─ click-wave.webm
│  └─ ...
└─ memes/                 可选，梗图；清单 dialogue.memes 里引用
   └─ pat.webp
```

打包成 zip 时，`manifest.json` 可以放在压缩包根目录，也可以整个包套一层文件夹
（常见于 Windows 右键“压缩到 zip”）。**只能套一层**，且 `manifest.json` 必须唯一。

---

## 2. manifest.json

```json
{
  "schemaVersion": 1,
  "id": "my-neko",
  "name": "我的猫娘",
  "version": "1.0.0",
  "author": "你的名字",
  "description": "自制猫娘形象包",
  "cover": "cover.webp",
  "source": "https://example.com/my-neko",
  "license": "CC BY-NC-SA 4.0",
  "dialogue": {
    "intro": "喵～我是你的猫娘。",
    "quips": ["今天也要加油喵。", "要不要摸摸头？"],
    "feed": ["小鱼干最好吃了！"],
    "hungry": ["肚子饿得咕咕叫…"],
    "sleep": ["我先眯一会儿喵。"],
    "memes": [
      { "file": "memes/pat.webp", "scenes": ["click", "feed"], "text": "摸摸头" }
    ]
  },
  "i18n": {
    "en": {
      "lines": { "喵～我是你的猫娘。": "Meow~ I'm your catgirl." },
      "actions": { "待机呼吸": "Idle breathing" },
      "categories": { "待机": "Idle" }
    }
  },
  "slots": {
    "idle": ["待机呼吸"],
    "click": ["点击回应-挥手", "点击回应-害羞"],
    "feed": ["吃小鱼干"],
    "sleep": ["原地打盹"],
    "drag": ["被拖起来"],
    "sad": ["垂头丧气"],
    "happy": ["开心转圈"],
    "work": ["敲键盘"],
    "money": ["数金币"],
    "move": ["小步跑"]
  },
  "actions": [
    {
      "id": "待机呼吸",
      "category": "待机",
      "file": "animations/idle.webm",
      "frames": 120,
      "fps": 24,
      "durationMs": 5000
    }
  ]
}
```

### 2.1 顶层字段

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `schemaVersion` | 是 | 固定为 `1` |
| `id` | 是 | 2–32 位小写字母 / 数字 / `-` / `_`，以字母或数字开头，全局唯一 |
| `name` | 是 | 显示名称，最多 60 字 |
| `version` | 否 | 作者自己的版本号，例如 `1.0.0` |
| `author` | 否 | 作者名 |
| `description` | 否 | 商店/清单说明 |
| `cover` | 是 | 包内封面相对路径，支持 `.webp/.png/.jpg` |
| `source` | 否 | 素材来源，转载时建议填写 |
| `license` | 否 | 授权方式；对外分享时必须写清楚 |
| `slots` | 否 | 行为槽位，见第 4 节 |
| `actions` | 是 | 动作列表，1–500 条 |

保留 id（不能使用）：`v1`–`v6`、`gpt`、`gptv1`、`dsh1`。

### 2.2 actions[]

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `id` | 是 | 动作名，包内唯一，最多 60 字；中文可以直接用 |
| `category` | 是 | 动作分类；应用「选个动作」面板按它分组显示，请从第 3 节列表里选 |
| `file` | 是 | 包内相对路径，使用 `/`，不能以 `/` 开头或包含 `..`、`:` |
| `frames` | 否 | 帧数，仅作说明 |
| `fps` | 否 | 帧率，仅作说明 |
| `durationMs` | 否 | 时长（毫秒），仅作说明 |

自定义导入只支持 `.webm` 透明视频。官方内置的图集包（`kind: "sprite"`）不开放自制导入。

### 2.3 dialogue：台词与梗图

`dialogue` 可选；写了就必须至少有一条文字（`intro` / `quips` / `feed` / `hungry` /
`sleep` / `memes[].text` 之一）。

| 字段 | 说明 |
| --- | --- |
| `intro` | 切换到该形象时的开场白，单条 |
| `quips` | 闲聊台词数组，最多 300 条 |
| `feed` | 喂食后的回应 |
| `hungry` | 饥饿时的抱怨 |
| `sleep` | 去睡觉时的台词 |
| `memes` | 梗图数组，最多 100 张 |

每条文字最多 300 字，不能为空。

`memes[]` 每项：

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `file` | 是 | 包内相对路径，支持 `.webp/.png/.jpg` |
| `scenes` | 是 | 触发场景，可多选：`click`、`feed`、`hungry`、`sleep`、`ledger`、`work`、`error` |
| `text` | 是 | 梗图配文，也会显示在气泡里 |

没有 `dialogue` 的包会沿用应用的中性台词，不会报错。

### 2.4 i18n：英/日翻译

`i18n` 可选，只支持 `en`、`ja` 两种语言，每语言可含三张表：

| 表 | 键 | 值 |
| --- | --- | --- |
| `lines` | `dialogue` 里的原文（逐字一致） | 译文 |
| `actions` | `actions[].id`（图集包用动作名 label） | 译文 |
| `categories` | `actions[].category` | 译文 |

译文不能为空、最多 300 字。`lines` 的键必须在 `dialogue` 文字里能找到，`actions` /
`categories` 同理；没有 `dialogue` 时不能只带 `lines`（但可以只带动作名/分类译文，
plus 扩充包就是这样沿用宿主台词的）。

翻译可以只覆盖一部分，未覆盖的条目在英/日界面保留中文原文。

### 2.5 sprite：图集参数（仅官方）

`kind: "sprite"` 的官方图集包（如 GPT娘v1）用单张 `spritesheet.webp` 加 `sprite`
块描述排版，字段包括 `sheet`、`cellW`、`cellH`、`cols`、`rows`、`sequences`（每序列
`row`/`count`/`times`，可选 `frame` 起始列）、`map`（动作名→序列）与 `actions`
（key/label 列表）。自制包不支持 `sprite`，请导出 WebM 动作。

## 3. 推荐分类

`待机`、`点击回应`、`情绪反应`、`吃喝`、`玩耍`、`才艺表演`、`运动健身`、`日常起居`、
`手工节日`、`时节`、`工作职业`、`工作状态`、`余额`、`碎碎念`、`魔法特效`、`移动`、
`拖拽`、`换装造型`、`礼仪致意`、`未分类`。

分类决定“随机小节目”会抽到哪些动作。没有写 `slots` 时，应用会按分类和动作名关键字
推断待机、点击、吃喝、睡觉等行为；写了 `slots` 则完全以 `slots` 为准。

另外，应用「选个动作」面板会**按 `actions[].category` 分组**（同类归到一组，组名支持
英/日译文，见 2.4 的 `categories`）。因此请给每个动作都标上 `category`，并尽量从上面
列表里选稳定一致的分类名；没标的会归到「未分类/其他」。

## 4. 行为槽位 slots

槽位把动作绑定到固定交互。值可以是单个动作名，也可以是动作名数组（数组会随机抽一个）。
**槽位里引用的动作必须出现在 `actions` 里。**

| 槽位 | 触发时机 |
| --- | --- |
| `idle` | 待机循环、切换形象后、没有其他动作时 |
| `click` | 单击 / 连续点击桌宠 |
| `feed` | 喂白饭、喂零食 |
| `sleep` | “让它睡会”，会不间断循环播放 |
| `drag` | 鼠标拖拽悬空 |
| `sad` | 饥饿、心情低、工作出错 |
| `happy` | 开心、庆祝、喂食满意 |
| `work` | 番茄钟 / 工作状态 |
| `money` | 余额账本播报 |
| `move` | 走动、换位置 |

建议至少提供 `idle`、`click`、`sleep` 三个槽位；其余缺失时会回退到启发式或 `idle`。

## 5. 素材要求

- **容器/编码**：WebM，VP9，带透明通道（`ALPHA_MODE=1`），像素格式 `yuva420p`。
- **分辨率**：推荐 `640×360`（16:9），与内置素材一致；窗口会按 16:9 拉伸，其他比例会变形。
- **帧率**：12 或 24 fps。
- **时长**：单个动作建议 2–10 秒；`idle` / `sleep` 必须首尾衔接、可无缝循环。
- **画面**：人物居中，四周留出安全边距；不要带背景色、边框、水印。
- **音频**：可选，当前桌宠动作视频默认静音播放，音效由应用统一管理。
- **体积**：单个包建议 ≤ 200 MB；应用硬限制 zip 解压后 ≤ 2 GB、条目 ≤ 4000。
- **封面**：建议 3:4 或 1:1，透明或纯色底，≤ 512 KB。

编码示例（透明背景的 MOV/PNG 序列 → WebM）：

```bash
ffmpeg -i input.mov \
  -vf "scale=640:360:flags=lanczos" \
  -c:v libvpx-vp9 -pix_fmt yuva420p -crf 32 -b:v 0 \
  -row-mt 1 -lag-in-frames 25 -auto-alt-ref 1 \
  -an animations/idle.webm
```

编码后可用 `ffprobe` 自查：

```bash
ffprobe -v error -show_entries stream=codec_name,width,height:stream_tags \
  -of default=noprint_wrappers=1 animations/idle.webm
# 期望看到 codec_name=vp9、ALPHA_MODE=1
```

## 6. 校验与导入

1. 运行校验脚本：
   ```bash
   python tools/character-pack/validate.py 我的形象/
   ```
   脚本会检查清单字段、id、路径、封面/动作文件是否存在、槽位引用，并在装有
   `ffprobe` 时检查视频编码和透明通道。
2. 打包：
   ```bash
   python tools/character-pack/make_pack.py 我的形象/
   ```
3. 打开桌宠 **设置 → 桌宠形象 → 从本地文件导入（.zip）**，选择刚生成的 zip。
4. 导入成功后卡片会出现在列表里，点“使用”切换。

导入时应用还会做一次同样的校验，常见报错：

| 报错 | 原因 |
| --- | --- |
| `zip 内没有 manifest.json` | 清单不在根目录，或套了多层文件夹 |
| `zip 内含非法路径` | 条目里有 `../`、绝对路径、盘符或符号链接 |
| `id 是保留名称` | 改一个 id，例如 `my-neko-2` |
| `找不到封面文件` / `找不到动作文件` | 清单里的路径和实际文件不一致，注意大小写和中文名 |
| `找不到梗图文件` | `dialogue.memes[].file` 指向的图片不在包里 |
| `dialogue 不能为空` | 写了 `dialogue` 但所有文字都是空的 |
| `i18n.xxx.lines 的原文 '…' 不在包内` | 翻译的键和 `dialogue` 原文不是逐字一致 |
| `槽位 xxx 引用了不存在的动作` | `slots` 里写了 `actions` 中不存在的 id |
| `只支持 .webm 透明视频` | 动作文件不是 WebM，或误用了图集 |

## 6.1 包内文字与应用体积

应用发布包里只保留商店内容（缩略图、名称、许可说明），不内置任何下载形象的台词、
梗图或动作名译文。因此：

- 修改台词/翻译/梗图只需要更新形象包，不需要重发应用；
- 没安装的形象包，其文字不会出现在应用安装目录里；
- 卸载应用会连同 `%APPDATA%\dafeiyu-desktop-pet`（Lite 为
  `dafeiyu-desktop-pet-lite`）下的已下载形象包与状态一起删除。若想保留，请在
  卸载前把该目录备份出来。

## 7. 授权

自制包可以自用，也可以分享；对外分享时请确保人物立绘、动作素材的版权和授权允许再分发，
并在 `license` / `source` 中写清楚。应用会把 `license` 显示在商店卡片的提示里，`source` 作为出处记录保留在清单中。

---

## 8. 可选元信息与创作者模板

在 `schemaVersion: 1` 基础上可追加以下可选字段，旧版本应用会忽略：

- `minAppVersion`：最低应用版本，低于该版本会拒绝安装（如 `"1.5.3"`）
- `homepage`：作者主页或仓库地址
- `tags`：分类标签数组（如 `["猫娘","像素"]`）
- `updatedAt`：更新时间（ISO 日期字符串）

商店会显示 `version`；当远端目录的版本高于本地已安装版本时，卡片显示「可更新」。

创作者可以把仓库里的 `tools/character-pack/github-workflow.yml` 复制到自己的形象包仓库
`.github/workflows/character-pack.yml`，推送 `v*` tag 时自动执行 `validate.py`、打包 zip 并创建 Release。

## 9. 规范版本

本文件对应 `schemaVersion: 1`。后续字段只做向后兼容的增量扩展；不兼容改动会提升
`schemaVersion`，旧包仍按 v1 解释。
